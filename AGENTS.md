## Read before any TALABOT task
1. Confirm the exact request, assigned role, allowed actions, branch, commit SHA and one output.
2. Open [master Issue #26](https://github.com/merapplications-sketch/Talabat-v3/issues/26), read latest comments and the assigned issue, then read [owner agreements](docs/OWNER-AGREEMENTS-AR.md) and [PM continuity](docs/continuity/PHASE1-CURRENT.md).
3. Read [Rules](docs/ai/RULES.md), [Decision Protocol](docs/ai/DECISION-PROTOCOL.md) and [Source of Truth](docs/owner-playbook/SOURCE-OF-TRUTH.md).
4. When auditing pilot readiness, follow [Pilot Readiness Skill](.agents/skills/talabot-pilot-readiness/SKILL.md) and [Pilot Gates](docs/launch/PILOT-GATES.md).
5. Distinguish approved decision, source existence, test result, deployed behavior and future proposal; they are not interchangeable.

## Operating model
- First make the existing TALABOT customer, driver, merchant and admin features safe for a controlled pilot; then develop approved additions in later stages.
- Respect approved Customer Dynamic Marketplace B, Restaurant v1.6, Direction A, DineOut Gold, original logo/colours, Admin Template B and four KPIs, V04/UX-02, and existing PRICE/RATINGS/TIP evidence within its original scope.
- Keep original financial agreements CASH-01, RETURN-01 and SCOPE-01 intact. No autonomous changes to code, layouts, SQL/Supabase, Cloudflare, payments, MFA, roles, accounts, deployment, production data or approved policies.
- Work is assigned one role at a time. A GitHub comment or task does not start a paused ChatGPT Work chat.
- Findings require case ID, exact SHA/branch/environment, expected/actual, executable proof, status, severity, and next owner; never invent a PASS.
- Competitor research and abroad-payer/local-recipient ordering belong to future proposals, not today's implementation queue.
