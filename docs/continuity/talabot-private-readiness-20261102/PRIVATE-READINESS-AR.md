# تجهيز تحويل TALABOT إلى Private — للمراجعة فقط

تاريخ المراجعة 2026-11-02. المستودع `merapplications-sketch/Talabat-v3` ما زال Public. **إغلاق التزامن ثابت عند b30105bab2a3bfbc6764b17d620f4e6ad1a963b9**، بعشر حالات PostgreSQL الأصلية؛ التحققات الـ53 والإغلاقات السابقة لم تُعد. هذه المراجعة لا تغيّر كوداً أو نشرًا أو خصوصية أو وصول أشخاص أو رقعة خادم.

## الحكم المختصر

التحويل نفسه متاح دون اشتراك جديد، لكن **ليس آمناً تشغيلياً الآن**: التطبيق المنشور يعتمد GitHub Pages، والبديل لم يُجهز، وقائمة وصول المبرمجين والموصلات الخاصة وحد إيقاف تكاليف Actions غير متحقق منها. المقترح المجاني: Cloudflare Pages Free برفع يدوي لحزم واجهة فقط محددة بالـcommit؛ فصل المنتج عن معاينات البيانات الاصطناعية، دون نسخ المستودع العام أو نشر SQL/docs/tests.

## ما تحقق فعلاً

- API المستودع: private=false، المالك حساب شخصي `merapplications-sketch`، has_pages=true. الاتصال الحالي يعرض admin/push، لكن ذلك لا يثبت أذونات كل المبرمجين أو استمرار تثبيت التطبيق بعد التحويل.
- main الحالي `148cfae50000e983af2221a96057c507edac6d69`؛ لا workflows ملفات في شجرته. النشر قائم كـGitHub Pages dynamic workflow، وليس ملف CI عادي يمكن حسمه من غياب .github.
- أحدث نشر Pages في سجل Actions هو التشغيل [39172212084](https://github.com/merapplications-sketch/Talabat-v3/actions/runs/39172212084)، فرع `integration/customer-v80-current` وcommit `ca8808dd6dee4f4815a266ae9bb9ea20a155f892`. هذا يطابق مرجع النشر والرجوع المحفوظ، دون ادعاء إعادة مطابقة كامل البناء الحي في هذه الجولة.
- قراءة HTTP عادية لصفحة [customer.html](https://merapplications-sketch.github.io/Talabat-v3/customer.html) أعادت 200. قراءة نموذج raw.githack لمرشح 24a153 أعادت 403؛ هذا لا يثبت أن كل الروابط القديمة معطلة، ولا يثبت نتيجة تحويل لم يحدث.
- البحث المحلي عن raw.githack لم يعثر على مرجع. بحث GitHub code أعاد items=[] مع incomplete_results=true؛ **ليس جرداً كاملاً لكل الفروع أو الروابط التي أُرسلت خارج المستودع**. تعامل الخطة مع عائلة الروابط كاملة، ولا تختلق قائمة حصرية.
- في حساب Cloudflare المتصل، استعلام Pages projects أعاد صفراً. لا مشروع TALABOT بديل جاهز في هذا الحساب؛ لا نستنتج غياب مشاريع في حسابات أخرى غير متاحة.
- موقع المعمل `appgprj_6ae89780be308191b60e2938754c7d5b` نشط، version 2، access_mode=custom. له [الرابط القائم](https://talabot-finance-sql-lab-20261102.alwarikahtan.chatgpt.site). `.openai/hosting.json` يربطه بمصدر Sites مستقل. لم تُغيّر المشاركة أو النسخة أو النشر.
- أدوات GitHub المتاحة رفضت endpoints Pages/deployments/collaborators العامة بـINVALID_ARGUMENT؛ لم تُقرأ خطة فوترة الحساب أو الميزانية أو قائمة المتعاونين أو التطبيقات المثبتة. هذه **حدود فحص** وموانع قبول انتقال الوصول، وليست دليلاً على غياب الصلاحيات.

## تحويل الروابط المقترح، دون إنشاء عناوين وهمية

1. `https://merapplications-sketch.github.io/Talabat-v3/{customer,driver,merchant,admin}.html` ← أصل Cloudflare Pages جديد مع الملفات والمسارات والأصول النسبية نفسها. اسم المشروع والرابط النهائي لم يُحجزا أو يُنشآ. لا يمكن ضمان إعادة توجيه من github.io بعد إلغاء نشره؛ يجب تحديث الروابط وQR المحفوظة.
2. `raw.githack.com/merapplications-sketch/Talabat-v3/<ref>/<path>` و`rawcdn.githack.com/...` ← حزمة معاينة مستقلة ثابتة الإصدار، ببيانات اصطناعية وإغلاق اتصالها بالمشروع الحي كما في الأصل المعتمد. الأصول تُرفق بالحزمة ولا تُسحب من raw الخاص وقت التشغيل.
3. روابط الأدلة في GitHub ← تبقى SHA/path نفسها للمخوّلين؛ لا نفتح المستودع مجدداً لتوزيعها، ولا ننشر أدلة حساسة في مشروع الواجهات العام.
4. رابط معمل ChatGPT القائم ← يبقى كما هو دون إعادة نشر. ليس بديلاً منشوراً لإيصال R1.

الموقع الجديد له origin مختلف: تسجيل الدخول وتخزين المتصفح local/sessionStorage لا ينتقلان تلقائياً. التحضير اللاحق يجب أن يحافظ على مفاتيح أية نتيجة مالية غير محسومة ويمنع إعادة الإرسال بعد تغيير الأصل؛ لا نعتبر اختفاء حالة محلية تأكيداً للتسوية. يراجع الفريق روابط Auth/OAuth/العودة المسموح بها وCSP والمسارات والجلسات عند تجهيز المضيف، دون طلب سجلات أو اختبارات تقنية من المالك، ودون تغيير Supabase الآن.

## المجاني وحدوده

- GitHub Free يتيح مستودعات خاصة ومتعاونين بلا اشتراك جديد. لا نوصي بترقية Pro للمحافظة على Pages؛ ننقل الاستضافة بدلاً من الاشتراك.
- Pages Free للاستضافة الثابتة يكفي مبدئياً لهذه الملفات: حتى 500 build شهرياً و20,000 ملف و25 MiB للملف. الطلبات الثابتة مجانية وغير محدودة وفق وثائق Cloudflare؛ Functions/Workers/SQL/R2 خارج المقترح ولا تُفعّل. يُستخدم نطاق pages.dev المجاني، دون شراء نطاق. لم يُنشأ مشروع أو اشتراك.
- بعد Private، Actions ليست مجانية بلا حد كما كانت على Public. الوثائق الحالية تعرض GitHub Free: رصيد compute شهري مشمول بقيمة $12، و500 MB artifacts و10 GB cache؛ الرصيد مشترك مع بعض الخدمات وقد يختلف بحسب خطة الحساب. هذا **رصيد مضمّن لا رسم اشتراك مطلوب**. خطة الحساب ورصيده المتبقي وحد إيقاف الزيادة غير متاحة، فلا نضمن فاتورة صفر من الإعداد الحالي.
- شرط الصفر المقترح: تشغيل يدوي ومحدود فقط بعد التحقق من حظر الزيادة المدفوعة؛ إن تعذر إثبات الحظر تبقى Actions متوقفة عن التشغيل بعد التحويل ويستخدم الفريق بيئة محلية مجانية. لا self-hosted runner جديد على شبكة المشروع الحي، ولا larger runners، ولا artifacts/cache مدفوعة. لا إعادة تشغيل اختبارات مالية ناجحة للتحقق من تغيير الخصوصية.

## ترتيب لاحق معروض للموافقة، غير منفذ

1. الفريق يحسم وصول المبرمجين والتطبيقات المثبتة وخطة الحساب وحد منع كلفة Actions. تُعرض أية دعوة أو صلاحية جديدة ضمن الموافقة المحددة، ولا تُنفّذ الآن.
2. بعد الموافقة على الاستضافة المنفصلة: تجهيز/رفع **النسخة المنشورة ca8808dd نفسها** ومعاينات اصطناعية مستقلة فقط، مع بقاء العمليات المالية الجديدة A/R1 والحساب الحقيقي معلقة. Direct Upload اختير لتجنب نشر تلقائي عند push؛ إن اختير Git integration لاحقاً يحتاج موافقة مختلفة وتقييد المستودع/الفروع.
3. تحقق الفريق من الأصول والمسارات والجلسات على المضيف الجديد ونقل الروابط؛ لا قبول مالي جديد ولا إعادة فحوص مغلقة. الاحتفاظ بحزمة النسخة المنشورة والرجوع على المضيف البديل نفسه.
4. إصلاح جلب Actions الخاص قبل أي تشغيل، أو إبقاؤها بلا تشغيل؛ ثم تقديم نافذة تحويل Private محددة للموافقة. لا تحويل قبل صلاحية البديل ووصول الفريق.
5. بعد موافقة التحويل فقط: تغيير الخصوصية، وفحص وصول الفريق والمنع المجهول وحالة المضيف دون حركة مالية. إن ظهرت مشكلة يُصلح المضيف/الوصول مع بقاء البيانات؛ العودة إلى Public ليست إجراءً تلقائياً ولا خطة رجوع مضمونة لحفظ السرية.

التحويل لا يسحب نسخاً أو forks أو كاشات جرى تنزيلها حين كان المصدر عاماً؛ rawcdn يعلن التخزين الدائم بحسب URL. يمكن للفريق بعد موافقة مستقلة طلب purge للعناوين المعروفة، دون وعد بمحو كل النسخ. كود HTML/JS/CSS الذي يصل إلى المتصفح سيظل قابلاً للقراءة ولو صار مستودع التطوير خاصاً؛ لا يُستخدم Private لإخفاء أسرار داخل الواجهة.
