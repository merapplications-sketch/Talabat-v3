# A + R1 — اختبار PostgreSQL متعدد الاتصالات

أساس التطبيق والإغلاقات: 0651830fa96a776f435688a92cd4400824e7e504. لا تغيير في SQL A أو R1 أو ملفات التطبيق. التحققات الـ53 محفوظة ولا يعيدها هذا المسار.

المحاولة المحلية متعذرة: لا postgres/initdb/psql أو Docker/Podman؛ خريطة المستخدمين والمجموعات لا تتيح إلا 0 (سطر `0 0 1`)، CapEff=0 وNoNewPrivs=1. الانتقال إلى UID 65534 فشل بـ`setresuid failed: Invalid argument`. لم تُغيّر صلاحيات البيئة ولم يُتجاوز منع PostgreSQL القياسي لتشغيله كـroot.

البديل: مشغّل GitHub القياسي ubuntu-24.04 للمستودع العام، خدمة PostgreSQL 17.6 مؤقتة على loopback، دون أسرار أو بيانات حية أو نشر. الاعتماديات psycopg[binary] 3.2.10 وtyping_extensions 4.15.0. صلاحية workflow للقراءة فقط؛ لا خطوات تطبيق أو تغيير صلاحيات أو نشر، ولا رفع artifacts يستهلك مساحة مدفوعة. الأدلة الكاملة تخرج مضغوطة في سجل التشغيل وتُحفظ بعده بالمستودع.

الاختبار الجديد عشر حالات: A منفردة وA ثم R1؛ لكل منهما مفتاح واحد ومفتاحان لنفس السائق. حالات فشل الحفظ: commands مع A؛ receipt وروابط الطلبات مع R1. لكل حالة قاعدة مستنسخة جديدة من بنية المعمل السابقة وبيانات اصطناعية فقط. إدراج تفويض المحاسب الاصطناعي جزء من fixture محلي، وليس حساباً أو تفويضاً حقيقياً.

جلسة مراقب تمسك قفل السائق قبل بدء الطلبين، ثم تُثبت pg_stat_activity وpg_blocking_pids اختلاف PID وتداخل انتظار الأقفال. بعد فتح القفل، يجب أن يتطابق المبلغ مع 57+43=100، وأن يظهر كل طلب مرة واحدة فقط في النتيجة والتدقيق. R1 يجب أن تنتج إيصالاً واحداً مطابقاً للطلبات والمبالغ والتوقيت والأثر؛ المفتاح نفسه يعيد النتيجة نفسها. A القديمة قد تحفظ أمراً ثانياً بمبلغ صفر وطلبات فارغة للمفتاح المختلف؛ هذا أمر بلا أثر وليس تسوية مكررة. R1 ترفض الحالة الفارغة بـnothing_to_settle.

في سيناريو الفشل تفشل المعاملة الأولى عند موضع الحفظ المحدد، بينما الثانية منتظرة. تُحجز الثانية قبل COMMIT حتى يفحص المراقب قاعدة بلا أي أثر مؤكد للمعاملة الفاشلة، ثم تُؤكد الثانية وتُطابق المجموعة كاملة. فحص النتيجة يعيد الناتج المحفوظ دون تغيير البيانات.

حالة هذه النقطة: المصدر جهّز لمحاولة التنفيذ؛ ليست نتيجة نجاح. يُضاف الحكم بعد استلام نتيجة التشغيل. إن رفض GitHub إنشاء workflow أو تشغيله يبقى بند الاتصالات المتعددة مفتوحاً مع توثيق الرفض، دون اشتراك أو استخدام مشروع Supabase الحي.
