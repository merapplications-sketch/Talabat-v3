## حدود الربط بالأدلة السابقة

- الاختبارات المحلية لا تعيد إثبات سحب صلاحيات الموظف والمحاسب أو تعطيل الحساب أو RLS وتنزيل الإثبات عبر حسابات مختلفة. تبقى أدلتها السابقة مستقلة، ويُراجع ارتباطها بالمصدر ومخطط قاعدة البيانات الحاليين.
- بعض العيوب القديمة لها اسم إصلاح واختبار رجعي، دون معرّف ثغرة موحد في ملف الاختبار؛ لم تُختلق أرقام عيوب لها. الرابط `C24-CLIENT-01` مذكور في تقرير العيب الأصلي؛ بقية الروابط وصفية أو ASVS جزئية كما يوضح الجدول.
- `proof-access` لا يختبر V5.3.2 الخاص ببناء المسار، و`request-id-retry` لا يثبت V11.5.1. `admin-idle` لا يثبت مدة جلسة مطلقة. منع ضغطتين في العميل لا يثبت قفلاً أو idempotency في قاعدة البيانات.
- لا تُستنتج سلامة كاملة من وجود test يحمل اسم MFA أو proof أو finance. مجموعة DB تربط ملفات محفوظة بالبصمات ولا تعيد فحص الخادم؛ مجموعة headers تفحص العامل المبني محلياً ولا إعدادات المزوّد.
- توافق آيفون/أندرويد القديم والاتصال الضعيف، MFA والاستعادة الحيّة، إلغاء رموز/روابط المزوّد، التزامن المالي الحقيقي، استعادة النسخ الاحتياطية ووصول تنبيهات الحوادث تبقى مرتبطة بأدلتها الحيّة المنفصلة؛ هذه البوابة لا تغلقها.

## الاستخدام عند التسليم

يُرفق هذا الجرد بنتيجة البوابة الفعلية وبصمات المصدر/المخرجات والـcommit النهائي. تُفصل نتائج التشغيل عن وصف التغطية، وتُحدّث فقط الصفوف المتأثرة عند تغيير الاختبار. هذه اختبارات المنفّذ وليست اختبار اختراق مستقلاً ولا إعلان قبول ASVS شامل.

## الإضافة في .26 و.27

المجموعات العشرون أعلاه محفوظة. أُضيفت مجموعة release-integrity، فأصبح الإجمالي 21. اختبارات .26 العشرة تغطي المصدر والاختبار ودليل SQL والملفات الجديدة والحزمة والنتيجة الناقصة/الفاشلة. أضافت .27 أربع حالات لمطابقة محتوى commit: نسخة سليمة مقبولة، وتعديل/إضافة/حذف غير محفوظ مرفوض. الدليل continuation27/gate.log و.last-build receipt. لا تشمل هذه المجموعة حماية صلاحيات حساب النشر أو توقيعاً خارجياً مستقلاً، ولا تشغّل SQL حياً.
