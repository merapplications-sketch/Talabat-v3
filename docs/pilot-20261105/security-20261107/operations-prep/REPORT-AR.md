# TALABOT — تقرير التحضير التنفيذي والأدلة

تاريخ الفحص: 7 نوفمبر 2026 UTC. مصدر التطبيق .31: `ea65f5289f3d19ccc5d3dbb65b59650e23e01370`. تحققت أن المصدر نظيف، وأن الموقع active وآخر نسخة استضافة41 على الرابط المعتمد. هذه حزمة أدوات وأدلة؛ لم أغيّر كود التطبيق أو أنشر نسخة جديدة.

## المنجز فعلياً

1. قرأت خطة الحوادث والاستعادة السابقة وربطت التحضير بها دون إعادة اختبارات الحسابات والطلبات المغلقة.
2. نفذت فحصاً إضافياً لدوال الاستعادة الفعلية:12 سلوكاً محدداً نجحت، بما فيها منع النقر المكرر، الرجوع دون query/hash، معالجة انقطاع الاتصال، وعدم إخفاء فشل الخروج العام. Auth وDOM بدائل محلية؛ ليس اختبار بريد حي أو إلغاء JWT لدى المزوّد.
3. أعددت مدقق حزمة DB/Storage ببصمات وأحجام وجرد ملفات وحارس يرفض الاستعادة إلى المشروع الحالي والإنتاج. جرى اختبار ملفات اصطناعية سليمة ومعدلة وناقصة، وتكرار المسار والخروج من المجلد والروابط الرمزية. لم تُنشأ نسخة DB حقيقية ولم تنفّذ استعادتها.
4. أعددت نموذج تنبيه اصطناعي لا يمرر حقول الأسرار أو روابط التوكن أو الموقع، وفحصت حقن النص والرفض الدائم و429 وإعادة المحاولة المحدودة. لا إرسال خارجي، ولا ادعاء وصول إنسان بمجرد HTTP ناجح.
5. أعددت محاكاة محدودة تتوقف عند أول حظر أو timeout أو فشل خادم؛ لا طلبات فعلية إلى Auth ولا استهلاك حصة الشبكة الحالية.
6. نجحت19 حالة اختبار لأدوات التحضير. هذه لا تُضاف إلى عدد اختبارات التطبيق المنشورة ولا تعادل19 متطلب ASVS مغلقاً.
7. حفظت اختبارات المصدر والتحضير ونتائجها وبصماتها، وخطة التنفيذ المفصلة في EXECUTION-PLAN.md، وربطها بمعرفات ASVS في ASVS-DELTA.json دون تغيير نتائج المصفوفة إلى نجاح.

## الخطوات المطلوبة من المالك — قرارات فقط، لا أسرار

- البريد: اعتماد صندوق تملكه لاختبار رسالتين كحد أقصى. يمكن استخدام صندوق عضو موجود أصلاً في فريق Supabase دون إضافة عضوية؛ أو اختيار صندوق اختبار وSMTP مع كلفة معتمدة. أنا أتولى سيناريو الاستعادة والتحقق؛ كلمة SMTP تحفظ بلوحة Supabase نفسها فقط عند الحاجة.
- الاستعادة: تحديد رابط مشروع فارغ موجود يجوز استخدامه، أو اعتماد طلب عرض كلفة هدف جديد. أنا أتولى التصدير والجرد والاستعادة والفحص بعد توفر الوصول الآمن؛ لا تطلب الخطة منك إعداد النسخة بنفسك. لا تعِد تعيين كلمة DB الحالية لأجل الاختبار.
- التنبيهات: تحديد مستلم وقناة واحدة، والإذن بتنبيه TEST واحد. أنا أتولى الربط وقياس الوصول والتصعيد بعد اعتماد القناة. لا خدمة مدفوعة ضمنياً.
- حدود المحاولات: توفير هدف Auth مؤقت وخروج شبكة ثابت مستقل لا تستخدمه الجلسات المحمية. يمكن تجهيز هدف واحد للاختبارات المنفصلة بالتتابع، لا ضغط على المشروع الحالي. أنا أتولى الحسابات الاصطناعية والميزانية والتوقف وتوثيق الأثر على IP المشترك.

لا كلفة جديدة فُعّلت. كلفة SMTP والهدف والتخزين والشبكة لا يمكن تحديدها قبل اختيارها وعرض المزوّد؛ لا سقف مصروف فعلي مثبت. تفاصيل الشاشات والحفظ الآمن وحدود كل خيار في الخطة المرفقة.

## ما تعذّر بدليل

اختبار حماية السجلات السابق أُرسل ضمن معاملة اصطناعية تنتهي بـROLLBACK. انتهت مهلة التأكيد الأصلي للأداة بعد دقيقتين دون نتيجة تنفيذ. ليس رفضاً أمنياً مثبتاً للاختبار، وليس نجاحاً أو فشلاً لحماية السجلات. يلزم قبول نموذج تأكيد execute_sql الجديد أثناء صلاحيته حين يُستأنف هذا الاختبار؛ لم أكرر الطلب بعد انتهاء المهلة ولم أتجاوز الأداة.

البريد الحي، استعادة PostgreSQL وStorage، وصول التنبيه، وأثر حصة IP الفعلية: غير مختبرة. سبب كل منها والوصول والقرار المطلوب موضح في الخطة. غياب psql/pg_dump/docker محلياً ليس وحده حاجزاً يتطلب المالك؛ يمكن تجهيز الأدوات عند اختيار الهدف، لكن الاتصال الآمن والهدف ونسخة البيانات الفعلية غير متاحة الآن.
