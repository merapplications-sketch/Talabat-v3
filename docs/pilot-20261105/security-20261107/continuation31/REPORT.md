## الحدود والحالة المحمية

لم تتغير الحسابات الخمسة أو كلمات السر أو التصميم أو دخول الزبائن أو قواعد المحاسبة. الطلبات #1/#2/#3 وإيصالاتها لم تُعد تسويتها؛ مستحق #3 بقي دون تسوية. الإنتاج والطرق الداخلية والخدمات المدفوعة دون تغيير.

هذا عمل منفذ الإصلاح، لا اختبار اختراق مستقل. تسليم المراجع المستقل يشمل المصدر/بصمات الحزمة، المصفوفة الكاملة، سجل الأسباب والإصلاحات، اختبارات rollback ودليل التنظيف، وحدود الأدلة الحيّة والمحلية. لا إعلان جاهزية قبل استكمال الصلاحيات والمال والبيانات الحساسة ومعالجة أي عالية/حرجة مؤكدة.

التقرير يحفظ التقدم ولا يدعي استنفاد كل العمل التقني المتاح. نقطة الاستئناف الحالية مرفقة في CURRENT-RESUME.md؛ لا إعادة تسجيل MFA ولا إعادة اختبارات ناجحة غير متأثرة.

فحص إضافي لمساعد الإرجاع: authenticated وanon لا يملكان USAGE على return_private، وauthenticated لا يملك EXECUTE على view_case ولا SELECT على cases. استدعاء مباشر محدود بدور authenticated رُفض فعلياً permission denied for schema return_private. أُغلق مرشح الوصول المباشر لهذا المساعد فقط؛ لا قبول عام لكل المخططات.

استكمال الصلاحيات دون تغيير جديد للكود: ست حالات لموظف الطلبات نجحت؛ قراءة حالة الإرجاع واسترجاع نتيجته مقبولان عند active+orders، ومرفوضان عند تعطيل الموظف وعند إزالة orders. الزبون رأى خمسة مفاتيح حالة بلا paid/currency/open_claim/pending؛ السائق المشارك رأى التفاصيل المسموحة له، والغريب رُفض. هذه مقارنة بعقد التنفيذ الموجود وليست اتفاق حقول جديداً مفترضاً. تغيير إسناد السائق بعد إنشاء الإرجاع رُفض return_order_protected؛ لم يُعطّل الحارس لإكمال سيناريو غير مدعوم.

مرشح تغيير زبون الطلب: لا UPDATE على customer_id للدور المصادق ولا سياسة UPDATE على orders، ومحاولة مباشرة ببيانات اصطناعية رُفضت لصلاحية الجدول. البحث المحدود في نصوص مخططات التطبيق لم يجد UPDATE orders SET ... customer_id. لا يوجد استغلال مثبت لهذا المرشح؛ لا يساوي البحث النصي جرداً كاملاً لكل مسار ديناميكي/مزوّد.

لوحة Supabase: أُتيح طلب دخول آمن منفصل لقراءة إعدادات Auth التي لا توفرها الإضافة، وعاد declined. لم يُكرر الطلب ولم تُستخدم بيانات TALABOT لتسجيل دخول المزوّد. إعدادات اللوحة تبقى غير مختبرة حتى يختار المالك إتمام دخولها؛ جلسة TALABOT وMFA المكتمل لم يتأثرا.

فحص إضافي لنتائج المال المخزنة: finance_command_status وfinance_execute أعادا العلامة الاصطناعية للمحاسب الفعّال نفسه فقط. حساب مالي آخر لم ير النتيجة ورُفض replay بـrequest_conflict؛ تعطيل الموظف أو إزالة finance أعادا status=null وnot_allowed. أربع حالات × مسارين، دون خصم أو تسوية أو إنشاء إيصال. التنظيف أكد users/commands/staff=0. هذا دليل جزئي V8.2.1/V8.2.2/V8.3.2، وليس تزامناً مالياً حقيقياً.

اكتمل جرد منح مخططات التطبيق الخاصة: finance_private وreturn_private وsecurity_private وfulfillment_private وpilot_private، مجموع 20 دالة. لا USAGE ولا EXECUTE للمجهول/المصادق على هذه الدوال، وCREATE غير ممنوح للمصادق في جميع المخططات المجردة. الجرد دليل إعدادات؛ الاستدعاء المباشر المنفذ سابقاً يخص view_case فقط، ولا يغني عن اختبارات جميع الأغلفة العامة.
