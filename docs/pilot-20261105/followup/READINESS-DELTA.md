## ما أضيف فعلياً في التحضير

1. بريد GoTrue فعلي داخل المعمل إلى Mailpit محلي، وتأكيد التسجيل ثم العودة للواجهة بنفس الهوية. أربع نقاط نجحت في [المحاولة9](attempt-9.json)، ولا حاجة لإعادتها في اختبار الاستعادة الجديد.
2. ثبت غياب استعادة كلمة المرور بالواجهة. أضيف مسار بنفس المكونات: طلب محايد لا يكشف وجود الحساب، رابط للواجهة الأصلية، كلمة جديدة وتأكيدها، ثم تسجيل دخول جديد. لا تغيير أدوار أو تفويض. النتيجة النهائية تسجل بعد التشغيل، لا يُعتبر وجود الكود قبولاً.
3. حمل ممتد180ث للطلب/GPS مع قراءات أدوار متعددة. الجولة الأولى أكملت18رحلة بلا تكرار أو أخطاء، لكنp95=8643.2ms. سبب اختلافها عن رحلة التطبيق: اختبار polling أرسل استعلامorders عاماً لكل الأدوار، بينما ordersQuery الفعلي يرشح العميل/السائق/المطعم ويحدد حدود60/60/200 والإدارة300. pg_stat_statements يثبت99قراءة عامة بمتوسط4830.349ms؛ الكتابات بقيت بعشرات المللي ثانية. لا عطل تطبيق مؤكد من هذا القياس وحده، ولا نحذف الدليل أو نسميه قبول أداء. الجولة المصححة تستخدم المرشحات والحدود والأعمدة وفترات25ث للعميل و10ث للبقية، مع نفس التاريخ10000طلب. الاستعلام العام المكلف يبقى حد أمان/أداء موثقاً لواجهة البيانات، لا «اختناق محلول».
4. اختبار Storage API حقيقي منفصل، بسياسات صور الطلب المحفوظة فيpatch34، وبصورة اصطناعية وJWTs حقيقية محلية. المقصود فحص رفع/قراءة/روابط مؤقتة/أثر إثبات الصورة، واستعادة metadata مع ملفات فعلية. لا بديل مصطنع يسمح بإغلاق قبول Storage المستضاف.
5. محاولة Safari أصلي علىmacOS15 عبرsafaridriver في مشغلGitHubعام مؤقت. تختبر واجهة الاستعادة بعقدSDKاصطناعي معلن، وتتكامل الأدلة مع اختبارGoTrue/SMTP الحقيقي علىChromium. لا تمثلSafariآيفون ولاGPSأوطباعةجهاز، ولا تُسقط حدود الخلفية.

كل البيئات مجانية مؤقتة دون ربط أسرار أو بيانات حقيقية، ولا نشر أوSQLحي أوتفويض أوحركةمالية. القديم من الاختبارات المتجاوزة لا يُحسب نجاحاً جديداً. أي نقص بيئة أو اختبار يدوّن بحدوده؛ القرارات لا تعطل الفحوص المستقلة.
