# إصلاح متانة التنبيه وقبول المضيف المعزول

**التجربة الحقيقية غير جاهزة.** أُغلق عيب فقد التنبيه في المرشح، ونجح قبول إعدادات المعمل وقراءات الأدوار والبريد الاصطناعي. يحتاج القبول التشغيلي قناة المناوب والأجهزة والنسخ الخارجية ومطابقة المضيف الفعلي.

مصدر الإصلاح والفحوص `606da1133c1f554d4dbdac6f77995d584d1d9355`، فوق آخر حفظ `8b500ccf00e92ee0b462c49da8e126e40369c436`. إغلاق أول كاش والإرجاع محفوظ. جرى تغيير أداة المراقبة فقط من أدوات التشغيل، وإضافة فحصين محددين ومحدد تشغيل المعمل. ملفات التطبيق وSQL بقيت خارج الفروق.

## ما أُغلق فعلياً

- **عيب الحفظ والإرسال.** تُحفظ حالة المجسات وأحداث التنبيه في استبدال ذري واحد لملف الحالة. لكل حدث معرّف عشوائي ثابت طوال إعادة المحاولة. ملف JSONL ناتج قابل لإعادة البناء من السجل. إخفاق كتابته يبقي الحدث محفوظاً للتشغيل التالي. تُزامن الكتابات إلى القرص، ويمنع قفل الملف تشغيل عمليتين على السجل في الوقت نفسه.
- **التسليم المشروط بإيصال.** الإرسال الاختياري يستخدم `Idempotency-Key` نفسه مع كل محاولة. يبقى الحدث معلقاً حتى يعيد المستقبل إيصالاً مطابقاً لمعرفه. استلام المستقبل مع ضياع الرد أو فشل حفظ الإيصال محلياً يعيد محاولة المفتاح نفسه. عند تأكيد الإيصال محلياً يُتجاوز الحدث في التشغيلات التالية. يحافظ التسليم على ترتيب الحادثة والتعافي.
- **11 حالة موجهة ناجحة.** فشل outbox بعد حفظ الحالة، وتعطل المستقبل ثم عودته، والتعافي، وضياع الرد بعد الوصول، وفشل الكتابة قبل السجل وبعد تصدير outbox وبعد إيصال المستقبل، والتزامن، والإيصال غير المطابق وترتيب التعافي، ورفض التحويل HTTP، وترحيل السجل القديم، وتغير الحالات ضمن الثانية نفسها. بعض الحالات تختبر أكثر من خطوة. راجعت كذلك أربع نقاط عقد المراقب الأصلي لأن الدالة نفسها تأثرت. [دليل محلي مع بصمات المصدر](LOCAL-EVIDENCE.json)
- **25 نقطة للمضيف المعزول.** نجح Auth مع تأكيد البريد، ومنافذ loopback، وضبط SMTP وREST، وقراءات الزبون والغريب والمطعم والسائق والمحاسب والمدير، وصلاحية مالية للموظف المفوض اصطناعياً فقط، ورفض الرمز غير الصحيح واختيار المخطط الخاص. بقيت RLS ومنع القراءة المباشرة للمخططات الخاصة. وصلت رسالتا التأكيد والاستعادة عبر SMTP فعلي إلى Mailpit، وعادت روابطهما إلى التطبيق المسموح وبنفس الهوية رغم طلب وجهة تحويل غير مسموحة. [الدليل](HOST-EVIDENCE.json) · [تشغيل ناجح 42106657113](https://github.com/merapplications-sketch/Talabat-v3/actions/runs/42106657113)

إعداد المعمل مأخوذ من المصدر والكتالوج المحفوظ. عدد الطلبات بقي صفراً في فحص المضيف. الخدمات والبيانات اصطناعية مؤقتة وقد أُزيلت بنهاية التشغيل. القراءة الإدارية أظهرت قائمة فروع تطوير Supabase فارغة، ولا تتوفر إعدادات المضيف الحالية كاملة عبر أدوات القراءة المتاحة. قبول Mailpit يثبت التسليم داخل المعمل، وتبقى صناديق البريد الخارجية وإعدادات SMTP الفعلية ضمن المتبقي.

## تشغيل الأداة وعقد المستقبل

تحافظ الأداة على `--config` و`--state` و`--outbox` ودالة `check(config, prior)` وحقلي الناتج `healthy` و`events_written`. أصبح ملف الحالة سجلاً ذا إصدار `journal_version=1` يحتوي `health` و`events` و`legacy_outbox`. تُقرأ اللقطة القديمة تلقائياً، وتُحفظ أحداث outbox القديمة كما هي ضمن تاريخ غير محسوم التسليم. يُظهر الناتج عددها في `legacy_unconfirmed` ولا يعيد إرسالها تلقائياً. أي تنبيه سبق فقده قبل الإصلاح يحتاج مراجعة تاريخية، إذ لم يُحفظ له سجل يمكن استعادته.

ملفات الحالة وoutbox والقفل تخص مثيلاً واحداً من المراقب. تحفظ في قرص دائم خاص بمستخدم التشغيل وتُؤخذ نسختها معاً. يُحتفظ بالسجل أثناء التجربة، وأي حذف أو تدوير يحتاج حفظ إثباتات الاستلام ومصالحة التاريخ. تشغيل الأداة مجدداً يعالج الأحداث المعلقة تلقائياً. الجدولة والتوقيت والتصعيد ما زالت مقترحات تحتاج الاعتماد وإعداد التشغيل.

مثال إعداد اختباري، يُستبدل اسم المجس وعنوانه بعنوان معزول مسمى لدى الفريق.

```json
{
  "endpoints": [
    {"name": "isolated-health", "url": "http://127.0.0.1:9999/health", "timeout_s": 5}
  ],
  "delivery": {
    "url_env": "TALABOT_TEST_ALERT_URL",
    "headers_env": {"Authorization": "TALABOT_TEST_ALERT_AUTH"},
    "timeout_s": 5
  }
}
```

```sh
python3 ops/pilot-watchdog.py --config /secure/pilot/config.json --state /secure/pilot/state.json --outbox /secure/pilot/outbox.jsonl
```

يحدد فريق التشغيل متغيري البيئة من مخزن الأسرار. HTTP مقبول للمستقبل على عنوان loopback حرفي فقط، وسائر الوجهات تحتاج HTTPS. الأداة ترفض تحويلات HTTP. عند إغفال `delivery` تعمل المراقبة والتخزين المحلي فقط. تتضمن النتيجة `pending_delivery` و`deliveries_confirmed` و`delivery_error`، وتعيد CLI رمز خروج غير صفري عند فشل التسليم. يبقى الحدث في الملف عند فشل العملية أو توقفها.

يتلقى المستقبل JSON للحدث يحتوي `id` و`type` و`endpoint` و`at`، ورأس `Idempotency-Key` المطابق. يعيد 200 أو 201 مع إيصال من الشكل التالي بعد إثبات أثر التسليم لديه.

```json
{"event_id": "<same-event-id>", "status": "delivered", "receipt_id": "<durable-receipt-id>"}
```

**شرط منع التكرار عند ضياع الرد.** يحتفظ المستقبل بمعرف الحدث وإيصاله حفظاً دائماً، ويعيد الإيصال ذاته لكل محاولة لاحقة بالمفتاح والمحتوى نفسيهما. يجب أن يشمل منع التكرار أثر الإشعار في القناة المختارة، أو أن تدعم القناة المفتاح نفسه. إذا كانت القناة ترسل الإشعار ثم تسجل المفتاح دون ضمان ذري أو دعم للمفتاح عند المزوّد، يبقى احتمال التكرار قائماً عند تعطلها بين الخطوتين. المستقبل الاصطناعي في الفحص يستخدم قيداً فريداً في SQLite، وصف الاستلام نفسه يمثل أثر التسليم الاصطناعي. التشغيل الحقيقي يحتاج إثبات عقد القناة قبل القبول.

الإيصال الآلي منفصل عن إقرار المناوب البشري. نجاح الفحص المحلي لا يغلق وصول الإشعار للمناوب أو الإقرار أو التصعيد أو التعافي في قناة الاختبار.
