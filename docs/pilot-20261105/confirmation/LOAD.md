# حمل الطلب والتتبع في المعمل

[الحمل المتدرج](staged-load.json) قبل إضافة حارس الحصر: 5 و10 و20 رحلة متزامنة، 105 طلبات مكتملة و2693 استجابة HTTP على ثلاث مراحل كل منها 60 ثانية، بلا أخطاء. بلغ p95 في مرحلة 20 رحلة 39.93ms.

[الحمل المتأثر بحارس الحصر](admission-load-1.json): 42 هوية GoTrue و20 رحلة متزامنة، 60 طلباً مكتملاً و1496 استجابة خلال 60 ثانية. 0% أخطاء، لا طلبات مكررة أو عالقة. p95=86.33ms وp99=182.14ms، وأقصى زمن 315.58ms. شمل عروض السعر والموافقة وتقدم الطلب وقراءات الموقع، مع 10 آلاف طلب تاريخي. أعيد تفعيل حراس الإدخال قبل جميع الطلبات المقاسة. القفل الذري يسلسل قبول الطلب لحماية السقف؛ متوسط SQL للإنشاء 91.252ms في هذا التشغيل، ولا تعد مقارنة تشغيلين منفصلين عزلاً لأثر القفل.

المعمل يختبر استدعاءات HTTP بهويات مستقلة لمطعم اصطناعي واحد؛ لا يقيس شبكة الهاتف أو Realtime أو Push أو دقة GPS والخلفية أو ساعات تحمل المضيف. لا يُستنتج منه سقف إنتاج.

السقف الاحترازي السابق يبقى للمراجعة: **3 مطاعم، سائقان، 10 زبائن مدعوين، 3 طلبات نشطة و20 طلباً يومياً لمدة 3 أيام**، بمنطقة محدودة في دوشنبه ووردية واحدة. الثلاثة النشطة أقل من أدنى مرحلة اختبرت خمس رحلات؛ بقية الحدود قيود تشغيلية، لا نتيجة استقراء. لا دفع من جيب السائق قبل قبول مسار المطالبات أو اعتماد نموذج مستقل لا يحتاجه.
