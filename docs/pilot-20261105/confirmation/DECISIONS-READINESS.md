# تسليم المرشح وحكم الجاهزية

**تأكيد أول كاش مكتمل في المرشح واختُبر معزولاً؛ التجربة الحقيقية غير جاهزة.** أُقفل مسار الموافقة وتغيّر العرض وتوزيع السائق داخل المعمل. مسار مطالبة السائق، والتحقق على المضيف والأجهزة، وإعداد التشغيل ما زالت شروطاً قبل الإتاحة.

[تنفيذ الموافقة وحدوده](IMPLEMENTATION.md) · [الأدلة والتشغيلات](EVIDENCE-INDEX.json) · [الحمل والسقف المقترح](LOAD.md) · [اختيار حزم الاختبار](TEST-SELECTION.md)

المعتمد: في إلغاء الزبون بعد استلام السائق وانطلاقه، المطعم الموافق مسبقاً يستلم الوجبة ويرد المدفوع فعلياً، والمنصة تتحمل أجرة التوصيل المتفق عليها. المبلغ غير المسترد يبقى مطالبة مفتوحة ولو كان رصيد الكاش صفراً. لا نطبق هذا تلقائياً على خطأ المطعم أو السائق أو المنصة، ولا نضيف ضماناً لأصل المبلغ.

خطة التفعيل والرجوع [للمراجعة فقط](../ACTIVATION-REVIEW.md). إيقاف الاستقبال يحفظ الطلبات المؤكدة وسجل الموافقات؛ لا إعادة طلب غير محسوم ولا حذف سجل أو رجوع مالي تخميني. إغلاق التزامن ثابت، وتحويل المستودع إلى Private مؤجل، وتعديل طريقة انضمام السائقين مطلب مفتوح. لا نشر أو SQL حي أو حركة مالية أو تفويض أو دمج main أو شراء.
