## موانع التفعيل، ومسؤوليتها على الفريق

1. **المضيف:** مطابقة SQL وRLS وgrants وAuth hooks، واختبار إعدادات Auth/PostgREST وSMTP/reset وروابط التأكيد وRealtime وStorage وعزل صور التسليم. قراءة المستشار أبلغت hibernation؛ لم ننفذ wake أو SQL حي. نجاح الربط المحلي لا يثبت إعدادات المضيف.
2. **الأجهزة:** Safari/iPhone وAndroid فعليان، GPS ورفض الإذن وقدم الموقع، تنزيل الإيصال وحوار الطباعة والطابعة عند الحاجة. يتولى الفريق ذلك دون تكليف المالك بتسجيلات. Chromium/PDF لا يغلق هذه البنود.
3. **الحماية التشغيلية:** نسخة مشفرة خارجية مع استعادة البيانات والملفات، وتحديد RPO/RTO ومسؤول النسخ. ربط مراقبة دورية بمناوب وبديل وقناة تنبيه فعلية؛ أداة watchdog الحالية تكتب outbox فقط ولا تعمل كخدمة.
4. **سياسة المال:** اعتماد تسعير ودوام المطاعم، الإلغاء بعد التحضير، جهة سداد مستحق المطعم والسائق، وحماية أي مبلغ يقدمه السائق. إلى أن تُعتمد السياسة، لا رحلة تتطلب دفع البضاعة من جيب السائق. تسجيل العمولة والمستحق ليس إثبات صرفهما.
5. **حصر التجربة:** الحارس مفروض ومختبر معزولاً؛ تبقى أسماء المشاركين والمنطقة والساعات والسقوف الفعلية غير معتمدة. إذا بقي Storage غير مقبول، يجب حجب مسار ترك الطلب عند الباب قبل إتاحته، لا افتراض أنه معطل الآن.
6. **الحساب:** البيانات الحقيقية للمحاسب وقائمة صلاحياته ومراجعة هويته؛ التفويض لاحق وضمن الموافقة المحددة فقط.

هذه موانع متفاوتة: بعضها نقص مصدر مثبت، وبعضها تحقق أو قرار مفتوح. ليست جميعها أعطال تطبيق. لا نعيد الفحوص المغلقة أثناء استيفائها.

## تجربة مقترحة وليست معتمدة

تجربة ويب في المقدمة فقط: مشرف تشغيل مناوب وبديل يتابعان المطعم والسائق، مع اتصال مباشر عند التأخر. يجب تسمية الشخصين وتوفير وسيلة الاتصال قبل التشغيل؛ لا نختلقهما. لا وعد بتنبيه أو GPS مستمر والتطبيق مغلق، ولا استقبال طلب إذا تعذرت المتابعة.

عند التعطل: وقف استقبال الجديد، تواصل بشري بمرجع الطلب، توثيق الحالة والتوقيت، وقراءة المفتاح الأصلي قبل أي إعادة إرسال. النتيجة المالية غير المحسومة تجمّد ولا تكرر. تراجع الطلبات الجارية واحدة واحدة، ولا تلغى بعد التحضير أو دفع السائق دون السياسة المعتمدة. غياب إقرار المطعم دقيقتين يستدعي متابعة؛ بعد خمس دقائق يوقف الاستقبال لذلك المطعم إلى الحسم.

إيقاف فوري عند أثر مكرر، تسرب بيانات، ادعاء دفع غير حقيقي، أو انحراف كاش. حدود مراقبة مقترحة: أخطاء تتجاوز 1% أو p95 يتجاوز ثانيتين لخمس دقائق، أو فقد متابعة المناوب. موقع أقدم من 60 ثانية لا يوصف بأنه حي؛ تتحول المتابعة إلى الاتصال. زيادة السقف تحتاج مراجعة وردية مستقلة.
