## الموانع والإصلاحات بالترتيب

1. الفريق يطابق الخادم الحالي ويستكمل Auth/SMTP/Realtime/Storage والعزل والنسخ الحقيقية؛ الوصول الحالي لم يسمح بحسم إعداداته. A وR1 وحراس السلامة **غير مطبقة حياً**.
2. الفريق يغلق Safari/iPhone وAndroid وGPS والطباعة على أجهزة فعلية. البيئة الحالية Linux/Chromium لا تغلقها، ولا يطلب من المالك جمع دليل تقني.
3. ربط مراقبة وتنبيه بمناوب حقيقي وبديل، واعتماد نطاق وساعات وسقوف مفروضة. Push الخلفية وحزم المتاجر **ناقصة بالمصدر**؛ تجربة تعتمد على تشغيل في الخلفية غير جاهزة. يمكن مراجعة تجربة ويب في المقدمة مع دعم بشري، بعد استيفاء بقية الشروط.
4. اعتماد سياسة الإلغاء وتمويل بضاعة المطعم وضمان مال السائق، وتوفير بيانات حساب المحاسب الحقيقي. لا حساب بديل أو بيانات مختلقة أو تفويض الآن.
5. بعدها فقط يعرض تفعيل منسق للنسخ والرقع والتفويض في نافذة محددة، مع تحقق وخطة توقف ورجوع تحفظ الآثار. [طلب التفعيل للمراجعة](ACTIVATION-REVIEW.md).

المقترح التشغيلي غير المعتمد:3 مطاعم، سائقان،10 زبائن مدعوين،20 طلباً/يوم،3 أيام،3 طلبات نشطة، في منطقة محدودة ودوام11–15 بدوشنبه. هذه حدود احترازية مقترحة، وليست قيوداً مفعلة أو سعة حية مثبتة.

لا شراء أو اشتراك نُفذ، ولا يلزم حساب متجر لتجربة ويب. رسوم المتاجر لاحقاً فقط إذا اختيرت: Apple99دولار/سنة، Play25دولار مرة واحدة؛ الأجهزة والبريد والدعم بحسب المتاح، ولا سعر مختلق أو ترقية مدفوعة تلقائية. [متطلبات المتاجر الحالية والتكلفة](PLATFORMS-COSTS.md).

دفتر الصرف والمقاصة والقبض الجزئي والتنبيهات المالية الدائمة تبقى مراحل مستقلة غير مكتملة. لا SQL حي أو تفويض أو حركة مالية أو نشر أو دمجmain أو تغيير خصوصية حصل ضمن هذه المرحلة. لا نطلب موافقة على تشغيل غير جاهز؛ طلب التنفيذ اللاحق يجب أن يسمي النسخ والنافذة والأشخاص والحدود بعد إغلاق الموانع.
