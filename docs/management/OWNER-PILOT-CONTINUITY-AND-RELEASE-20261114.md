# TALABOT — برنامج المالك الموحد للإطلاق والاستمرارية
**التاريخ:** 2026-11-14 / دوشنبه | **الحالة:** توجيه المالك محفوظ للتنسيق والمراجعة، وليس إطلاقًا أو تغيير كود معتمدًا
**النطاق:** مستودع التطبيق merapplications-sketch/Talabat-v3 + لوحة الإدارة merapplications-sketch/talabot-tailadmin-review. **حدود صارمة: مشروع TALABOT فقط، دون تعديل أي مستودع آخر.**

## 0. قرار المالك — ما الذي يجب أن يحدث أولًا
1. ننجز **نسخة TALABOT التجريبية الأولى** بمظهر معتمد جذاب وسرعة وسلامة تشغيل حقيقية للعملاء والسائقين والمطاعم والإدارة، دون إعادة تصميم مُجاز أو إقحام ميزات منافسين.
2. يشترط المالك **تتبعًا حيًا للخريطة للعميل والسائق والإدارة** في قبول النسخة التشغيلية الأولى، مع اختبار دقة الموقع، تحديثه، خصوصيته، استعادة الشبكة وعمل هاتف السائق بالخلفية. هذا **متطلب قبول جديد من المالك**، وليس إثباتًا أن ميزة من هذه الميزات تم تنفيذها.
3. البداية تجريبية منخفضة التكلفة قدر الإمكان، لكن حماية بيانات الطلبات والأموال، قبول أدوار وصلاحيات، والقدرة على الاستعادة شروط لا تُختزل لتوفير التكلفة.
4. **أفكار المنافسين والجديد** تبقى قائمة مقترحات مرتبة وملفًا مستقلاً؛ لا تنفيذ دون موافقة مالك جديدة محددة بالنطاق والكلفة وتأثيرها.
5. يمتلك المالك حساب Google Play، وليس Apple Developer حاليًا. تُجهز متطلبات Android وiOS للنشر عندما تجتاز النسخة الاختبارات، ولا يُشترى اشتراك أو يُرسل تطبيق دون إذن.
6. مستودعا GitHub الآن عامان؛ يرغب المالك بتحويل المستودع الأساسي إلى **خاص بعد جاهزية أول نسخة**، مع خطة مسبقة لفرق العمل والربط والنشر وعدم كسر المعاينات؛ لا تغيير Visibility تلقائيًا.
7. محادثة ChatGPT Work مقيدة مؤقتًا ويُتوقع عودتها الأربعاء **2026-11-18**. العمل الحالي يحفظ الدلتا على GitHub كي يستأنف Work من HEAD وليس من رسائل قديمة. **إنشاء Issue/تعليق لا يوقظ Work تلقائيًا.**

## 2. من يفعل ماذا؟ طريقة منع التشتت بين المحادثات

| الدور | المسؤولية | ما لا يحق له فعله تلقائيًا |
|---|---|---|
| **المالك** | اعتماد النطاق، التغييرات المحمية، التكاليف، النشر والإطلاق | لا تُفسر ملاحظته التصميمية كتفويض مالي/تقني عام |
| **المدير / المنسق** | تخطيط الدفعات، ترتيب الأدوار، قراءة أحدث HEAD/Issues، استلام الأدلة، حل التعارض، تقرير GO/NO-GO | لا يتولى تبرير PASS دون اختبار، ولا يغير العقود بالافتراض |
| **المبرمج** | إصلاح العيوب المعزولة بعد إثباتها، كتابة اختبارات الوحدة/التكامل، بناء النسخة | لا يعدّل تصميمًا أو مالًا أو صلاحيات/SQL معتمدة دون تفويض صريح |
| **المصمم** | مطابقة الهوية والواجهات وتدفق العميل والسائق والتاجر، RU/EN/TG والهاتف | لا يبدل Home B/Details v1.6/Direction A/DineOut Gold/UX-02 V04 دون قبول |
| **المستشار التقني المستقل** | فحص أمن API/Auth/RLS، المعاملات، G1، قدرة الحمل، إصدار البيئة | لا يعتدّ بفحص مصدر بدل E2E/بيئة تشغيل |
| **مدقق UX المستقل** | تحقق بصري على المرشح التنفيذي وSafari واقعي، مع الأدلة قبل/بعد | لا يُعتمد تدقيق ذاتي للمصمم بديلًا |
| **مسؤول النشر/التشغيل** | مطابقة SHA والنشر الآمن والمراقبة والنسخ والتراجع/الحسابات | لا ينشر أو يشتري/يغير Cloudflare/Supabase دون سلطة منفصلة |

**النشاط المتوازي:** يمكن للمصمم والمبرمج العمل بالتوازي فقط على نطاقين غير متعارضين بعد تكليف محدد، وتحت مدير واحد؛ **المسار الحالي Stage19 يقصر التنفيذ التالي على الناشر** حتى ينتهي. لا نفرض 7 أعمال على 7 محادثات دفعة واحدة.

## 3. بروتوكول تسليم إلزامي يحل مشكلة انتهاء المحادثات

1. افتح **MASTER #26**، اقرأ آخر تعليق، ثم التكليف المرتبط، ثم أحدث SHA لفرع الدور. لا تثق في نص نموذج أو وعد «خلص» دون رابط.
2. عند بدء دفعة سجّل: هدف واحد؛ ماذا تغيّر منذ آخر مرة؛ مرجع موافقة المالك؛ فرع/commit موجود؛ مالك التنفيذ؛ الملفات المسموح لمسها؛ الممنوع؛ اختبارات قبول؛ شرط إيقاف.
3. نفّذ **دفعة متكاملة واحدة** في نطاقها، ولا تسلّم لكل زر على حدة. احفظ الكود/الأدلة على فرع واضح، مع test results وفروق ومصور/روابط إن كانت تنفيذية.
4. المراجع الآخر مستقل عن صاحب التعديل: يختبر نفس SHA والفروق فقط، ويصرّح PASS/FAIL/BLOCKED وحجم العينة وأي شيء لم يُختبر.
5. بعد استلام المدير يُحدّث MASTER #26 مع **حالة كل مسار** وجدول blockers، ويُسند **المنفذ التالي فقط**. لو ماتت المحادثة، المحادثة البديلة تقرأ GitHub وليس نص محادثة مخزنًا.
6. كل مهمة مؤجلة تحمل حالتها: APPROVED, ACCEPTED WITH EVIDENCE, IN_PROGRESS, BLOCKED, NOT_TESTED, OWNER_DEFERRED, FUTURE_AWAITING_APPROVAL. **لا تُغلق Issues القديمة جماعيًا**؛ اشرح أولًا أرشفتها وتاريخها.
7. قبل كل Merge/Deploy/سحب إلى main: تحقق صاحب الإصدار، أثر القاعدة، بيانات الإنتاج، متطلبات العودة وملكية القواعد المعتمدة، وموافقة مالك منفصلة.

## 5. سياسة المستودعات والملكية

- المرجع الفعلي هو GitHub داخل كل مستودع: تقرير/قرار/commit/اختبارات، وليس Claude أو محادثة Work منفصلة أو جهاز مطور.
- مجلد خطط المالك مستقل عن الفروع الأصلية؛ **الملف التنظيمي لا يصبح policy نافذة بمجرد رفعه**. المصدر الأصلي للاتفاقات هو المرجع الأعلى.
- بعد أول نسخة تجريبية معتمدة: تدقيق الأسرار/التبعيات والأصول وforks، جرد أعضاء الفريق وصلاحياتهم، مراجعة روابط build/CI/صفحات المعاينة ثم تحويل المستودع الأساسي إلى Private بموافقة المالك. مستودع TailAdmin أيضًا عام ويحتاج قرار حماية مماثل.
- تحويل Repo عام إلى خاص لا يمحو fork عامة قديمة، وقد يُعطّل GitHub Pages المجاني. يجب تأمين بديل عرض قائم وفحص الروابط قبل التغيير. لا تجعل خصوصية المستودع سببًا لتوقف التطبيق.
- لا ننشر أسرار Supabase/Cloudflare، محاضر العملاء، تفاصيل إشكالية أمنية قابلة للاستغلال، سجلات مفاتيح أو صور خاصة في مستودع عام، بما في ذلك Issue #26.
