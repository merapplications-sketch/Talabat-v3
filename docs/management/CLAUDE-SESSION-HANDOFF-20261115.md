## 3. توصيات تنظيم العمل (للمدير الجديد)
1. **التناسب:** مراجعة مستقلة كاملة فقط لما يمس المال، الصلاحيات، البيانات الحقيقية، أو الإنتاج. تغييرات المعاينة/النصوص/الواجهة الصغيرة: منفّذ + فحص آلي + لقطة.
2. **مانع الصلاحية يُحل خلال رسالة واحدة للمالك**، لا بمراحل: إما يمنح الأداة الصلاحية، أو ينفذ هو خطوة الرفع بنفسه بملف جاهز مع تعليمات قصيرة.
3. **قفل الإصلاحات:** كل خطأ مغلق = فحص آلي باسمه ضمن أمر واحد يُشغَّل قبل كل تسليم (`tools/` فيه ~30 سكربتًا مبعثرًا، بعضها لميزة السحب الملغاة).
4. **خريطة كود قصيرة** (ملف ودالة لكل مجال) و**STATUS** سطر لكل بند، حتى لا تقرأ كل مهمة الكود كاملًا أو السجلات الطويلة.
5. **ملف قواعد قصير:** `CLAUDE.md` الحالي جيد لكنه يحيل لعشرات الوثائق؛ المطلوب صفحة واحدة تكفي للبدء.
6. **الأولوية بعد Stage22:** العودة للإصدار التجريبي الحقيقي (F-01…F-04 ثم E2E الحرجة)، بتكليف متكامل واحد.
