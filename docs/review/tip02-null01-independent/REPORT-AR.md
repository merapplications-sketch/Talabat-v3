## مقارنة المصدر الكامل

1. TIP-02 فوق TIP-01: الفرق داخل المنشئ هو حارس المجال للإنشاء الجديد وتخزين القيمة الصالحة عبر `coalesce(p_tip,0)` بدلاً من قائمة القيم القديمة؛ باقي التعريف مطابق بعد هذين التغييرين. لم تتغير المعادلات أو HMACv1 أو حراس106.
2. NULL-01 فوق TIP-02: التغيير السلوكي الوحيد في التعريف الكامل هو إضافة رفض NULL إلى شرط الإنشاء الجديد، مع تعليقات وصفية. التوقيع وDEFAULT0 وSECURITY DEFINER وsearch_path وextra_float_digits محفوظة.
3. قارنت كتالوج الدوال الفعلي داخل قاعدة الاختبار قبل NULL وبعده: تغير جسم `security_private.create_order103` وحده؛ المالك والخصائص وACL ثابتة. لم يُمنح authenticated تنفيذ المنشئ الخاص.
4. موضع الرفض يبقى بعد الهوية والتفويض والاسترجاع، ثم الأقفال وإعادة الاسترجاع وحاجز closure، وقبل إنشاء الطلب وآثاره. بقاء `coalesce` في موضع التخزين لا يحول NULL الجديد إلى0 لأن الحارس يسبقه. التاريخ يُسترجع قبله دون تطبيع المدخل القديم.
5. العميل يمرر NULL الصريح كما هو للاسترجاع الخادمي، ويميزه عن غياب الخاصية=0. لا يملك الموك إثبات سلوك decoder أو منح HTTP الحقيقيين.
