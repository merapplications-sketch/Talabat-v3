## القرار المنفذ وحدوده

الخيارات السريعة5/10/20؛ خيار «مبلغ آخر» يقبل أعداداً صحيحة من1 إلى100، شاملاً الحدين.3 قيمة يدوية وليست زراً سريعاً. عدم الاختيار0؛ خيار «لا إكرامية» يبقى واضحاً. لا تُسقط القيم غير الصالحة إلى0.

الإكرامية تضاف كاملة إلى أجر السائق وفق المعادلة القائمة. حصة المنصة في fixture تخص التوصيل فقط؛ الزيادة في أجر السائق تساوي الإكرامية كاملة. لا تغيير للعمولة أو المحفظة أو النقاط أو تسعير الطلب أو حصة النقد.

**NULL الصريح منفصل وغير محسوم سياسياً:**
1. غياب معاملSQL يستعمل default0 القائم. غياب خاصيةtip في النواة أو المسودة يعني عدم اختيار0.
2. النواة لا تستخدم `o.tip || 0`؛ تنقلNULL الصريح كما هو، فلا تخلطه بغياب المعامل. المدخلات الرقمية الصحيحة لا تتغير.
3. مسارSQL يبقي سلوكNULL السابق: تخزين0 مع payload/HMAC يحتويNULL. لا اعتماده كسياسة جديدة ولا تغيير قيمه السابقة. اختبار مستقل داخل الحزمة يثبت أن إعادة المفتاح نفسه بـ0 بدلاً منNULL تتعارض.
4. NULL المخزن في مسودة لا يُعامل كغياب الحقل؛ يبقى إدخالاً يحتاج اختياراً صريحاً صالحاً. الواجهة لا تولدNULL كاختيار.
5. لهذا لا يُغلق TIP-G بالكامل. المطلوب من المالك عقدNULL الصريح فقط، لا إعادة اعتماد1..100 أو3 أو رفض الكسور/السالب/فوق100.

## فرق المصدر

### الخادم

`tests/tip02/acceptance.sql` إضافة بعد103→104→105→106→TIP-01. تعيد تعريف المنشئ نفسه بلا تغيير توقيع أو ACL أو خصائص SECURITY DEFINER/search_path/extra_float_digits.

بعد فحوص الهوية والاسترجاع الأول، ثم القفل والاسترجاع الثاني وحاجزclosure، وقبل إنشاء الطلب وأثر المحفظة:

```sql
if p_tip is not null and (p_tip < 0 or p_tip > 100 or p_tip <> trunc(p_tip)) then
  raise exception 'bad_value';
end if;
```

بعد ذلك تستعمل قيمة التخزين `coalesce(p_tip,0)` بدلاً من قائمة TIP-01. NULL استثناء توافق سابق كما سبق. المبلغ الصالح يُحفظ كما أُرسل. القيم غير الرقمية يرفضها توقيعnumeric قبل دخول الدالة؛ لا يُدّعى وجودclosure أو إيصال رفض خادمي محفوظ لتلك الحالة.

المداخل الأربعة: `place_order`، `place_order103`، `place_order104`، `security_private.create_order103`. المدخل الخاص اختُبر بمالك القاعدة المحلية، دون منح صلاحية جديدة للمستخدم. المداخل المستقلة القديمة خارج هذه السلسلة لا تتغير تلقائياً؛ قطع الكتاب غير المتوافقين يبقى شرط انتقال.

`SQL-DIFF.patch` يبيّن الفرق الكامل. لم يتغير HMACv1 أو canonical payload أو شروط العزل أو الحواجز أو epsilon. ملفات TIP-01 و103–106 الأصلية لم تُعدّل.

### العميل والنواة

- نجاح العملية يمسح الإكرامية المستهلكة من المسودة التالية حتى لو حُفظت تعديلات السلة. اختيار جديد صريح بعد الإرسال يُحفظ؛ ليس اعتماداً تلقائياً لإكرامية الطلب السابق.
