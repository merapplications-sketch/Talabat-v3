### الحد الأدنى للإصلاح المستقبلي — لم ينفذ

1. طبقة تصحيح مستقلة **بعد 106** تغيّر قبول الإكرامية للإنشاء الجديد في الجسم الفعال الواحد، بحيث تمر 5/10/20 كما اعتمدت، مع بقاء 0 لعدم الاختيار. لا تعدل الاختبارات التاريخية أو إعادة بناء 103/104 بأثر رجعي، ولا تغيّر HMACv1 أو تحويل p_tip داخل payload القديم.
2. ربط جميع المداخل أعلاه بالجسم المصحح، وحصر/إيقاف أي كاتب قديم عند الانتقال وفق الخطة المقبولة. لا إعلان اكتمال الإصلاح إذا بقي مسار منشور يمرر إلى جسم مختلف. التعديل الفعلي يحتاج تكليفاً مستقلاً.
3. الاسترجاع قبل قواعد الإنشاء الجديد يظل بعد التفويض: طلب قديم أُرسل بـ 20 وخُزن tip=0 يسترجع **قيمته المحفوظة 0**، حتى لو binding يحمي 20؛ لا تصحيح مالي رجعي. طلب قديم tip=3 يسترجع كما هو. لا تحويل binding أو إعادة توقيعه لتلائم القيمة المخزنة.
4. طلب غير محسوم يحتفظ بالمفتاح و payload الأصلي؛ إعادة التحقق أولاً؛ لا إنشاء بمفتاح بديل. نجاح محفوظ لا يعاد تسعيره؛ رفض مثبت له closure لا يعاد فتحه. إغلاق رفض ثم تصحيح صريح يستخدم دورة المحاولة المعتمدة، لا إعادة استخدام المفتاح بمحتوى مختلف.
5. **سياسة القيم خارج الخيارات غير مكتملة**:3 للطلبات الجديدة، القيم السالبة/الكسرية/غير finite/النصية، و NULL المباشر مقابل غياب المعامل. المصدر يبين سلوكه الحالي لكنه ليس اعتماداً تجارياً لكل تلك القيم. لا نعتمد إسقاطها بصمت أو قبولها أو خطأ جديداً هنا؛ يلزم عقد قبول/رفض صريح قبل إنهاء إصلاحها. قبول 5/10/20 وعدم اختيار 0 لا ينتظر إعادة قرار.

- السعر موجب finite وأقل من 100000، فلا يمنعه حارس السعر المقروء؛ قيمة rate10 تحقق قيد stores.earn_per_tjs. qty 1 تحقق قيد الكمية.

- حساب عشري مستقل بالاشتقاق: x=paid×10=120.0000001؛ ceil(x)=121. x−0.000001=119.9999991؛ ceil=120. الفرق نقطة واحدة. لم نشغّل JavaScript التطبيق أو SQL أو دالة المرشح.
- عموماً يظهر الفرق عند x=n+δ، حيث 0<δ≤0.000001. لو **ثبت** paid بمضاعفات 0.01 ومعدل صحيح، فلن تقع δ الموجبة بهذا المجال، وتكون الصيغتان متساويتين على ذلك المجال؛ لكن هذا القيد غير مفروض على سعر الصنف في المسار المقروء. لا نصنع قيداً لتبرئة epsilon.
