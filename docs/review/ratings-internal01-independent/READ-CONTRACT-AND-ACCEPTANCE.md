## 1. عقد موحد للفرع

هذه أسماء حقول مفاهيمية وليست endpoint موجوداً أو تغيير مخطط معتمداً.

| الحقل/القاعدة | العقد المقترح |
|---|---|
| `store_id` | هوية سجل الفرع المقصود؛ كل قراءة وتعليق وحساب مرتبط بها، لا بالاسم أو Place ID |
| `brand_id`, `branch_name` | سياق عرض الهوية دون جمع متوسطات الفروع أو تغيير فرع الدبوس |
| `source`, `subject` | `talabot`, `restaurant`؛ ثابتان بلا fallback خارجي |
| `rating_count` | عدد `store_stars` غير NULL للفرع في سجل TALABOT الداخلي ذي المصدر الموثوق؛ لا عدد السائق أو عدد التعليقات أو عدد Google |
| `average` | إن كان العدد>0: نفس `round(avg(store_stars),1)` المقروءة؛ وإن كان صفر بعد نجاح القراءة: NULL. لا إعادة تقريب متوسطات الفروع ولا قيمة افتراضية |
| `state` | `ready` عند اكتمال بيانات صحيحة؛ `empty` فقط لقراءة مؤكدة ذات count0/averageNULL؛ `unavailable` للفشل أو بيانات متناقضة/حقول مفقودة. أي cached/stale يعلن كحالة حداثة مستقلة |
| حداثة القراءة | وقت الجلب لا يُسمى وقت آخر تقييم؛ `rating_updated_at` القديم ليس توقيتاً داخلياً مثبتاً. تحديد وسيلة ربط نسخة المتوسط/العدد والتعليقات عمل تصميم لاحق، لا ادعاء snapshot ذرية حالية |
| عدد1–4 | يعرض المصدر الداخلي إن اكتمل؛ لا Google ولا متوسط السائق. شرط5 القديم يخص اختيار المصدر بالعميل ولا يظهر كشرط قبول نجمة في SQL |
| الترتيب والفلاتر | تستخدم نفس المتوسط/العدد الداخليين؛ لا تغيير صيغة الترتيب المقبولة بذريعة توحيد المصدر. حالات unknown لا تُرقى إلى مرتفعة التقييم أو تتحول لمؤشر صفر مضلل |
| `reviews` | نص مطعم فقط، من تقييم داخلي مؤهل، عبر إسقاط مصرح؛ لكل عنصر مرجع عام غير كاشف ونجوم المطعم وتوقيت ونص مسموح. أسماء هذه الحقول وحدود إظهار الكاتب تحتاج اعتماد نطاق النشر |
| `review_count` | إن أتيح: عدد المراجعات النصية القابلة للنشر، مستقل عن rating_count. لا يساوي طول صفحة جزئية |
| بيانات ممنوعة من العرض العام | معرفات الطلب/الزبون/السائق، الهاتف، بيانات الحساب، `handled_by/handled_note`، ملاحظات السائق أو وسومه ضمن تعليق مختلط |
| التاريخ المختلط | لا تصنيف تلقائي للنص الحر على أنه عن المطعم ولا قصّه حسب كلمات. تظل القراءة العامة محجوبة للنص غير المثبت حتى حسم نطاق التعامل؛ المتوسط الداخلي لا يعتمد على قرار نشر التعليق |
| المعالجة المنخفضة | `handled_at` لحالة متابعة الدعم، لا حذف أو قبول نشر، ولا مرشح لاستبعاد النجوم السيئة. يبقى متوسط جميع النجوم الداخلية دون اختيار الإيجابيات |
| الاسترجاع | لا آثار كتابة في عقد القراءة. استرجاع التقييم الخاص بالطلب يخضع لملكيته وصلاحياته ولا يستخدم قائمة آخر300 لإثبات غياب سجل قديم |
| حالات المستخدم | لا توسيع أهلية تقييم الهدية إلى المستلم أو المجموعة إلى كل عضو، ولا منح المطعم سلطة إخفاء النجوم. لا تغير أهلية تاريخ قديم بمجرد تغيير الحساب/الفرع اليوم |
| التجزئة | قائمة المراجعات تتطلب ترتيباً ثابتاً وترقيماً يمنع فقد/تكرار العناصر، وعدداً كلياً مستقلاً عن الصفحة. لا اعتماد قائمة الإدارة المحدودة300 كقائمة كاملة |

لا يفرض العقد RLS جديداً أو دالة جديدة أو جدولاً جديداً. يحدد المخرجات والحدود التي يجب أن يحققها أي مرشح لاحق، بعد اعتماد التنفيذ، ويترك وسيلة التنفيذ للمراجعة المقيدة بالمصدر الفعلي.

## 3. القرارات والفجوات قبل التنفيذ

- مصدر TALABOT فقط، عدم خلط السائق، عدم Google fallback، وعدم حذف التاريخ: **محسومة بالسياسة** ولا يعاد طلب اعتمادها.
- المطلوب تحديده قبل نشر التعليقات: الحقول العامة وهوية الكاتب الظاهرة إن وجدت، وما يُنشر من النصوص التاريخية المشتركة مع السائق وكيف يثبت اختصاصه بالمطعم. أي توسيع للقراءة الخاصة أو تغيير eligibility/moderation هو تعديل عقد وصلاحيات يحتاج تكليفاً صريحاً؛ لا تنفيذه في ربط بسيط.
- التجميع والقيود والمنح الحالية وأهلية HTTP والجدولة/التحديث: دليل نشر واختبار لاحق، وليس قرار أعمال يرفع للمالك بدلاً من عمل فني.
- Google admin history يبقى محفوظاً؛ تحديث الملاحة الخارجية خارج نطاق هذا العقد.
- لا تبدأ الحالات RI-T01..19 هنا. الأولوية التالية للمراجعة المستقلة لإصلاح PRICE01-QA-01/02 بعد تسليم مصدره النهائي.
